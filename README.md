# RA4M2-frame

一个基于 **Renesas RA4M2** 的嵌入式项目模板，适用于课程设计、功能验证和瑞萨综合测评场景。

## 1. 项目定位

本工程是一个“可直接编译下载”的最小应用框架，目标是让你在现有模板上快速完成功能验证与测评项目开发：

- 提供完整的 FSP + 用户层分层结构；
- 提供常见外设模块（按键/LED/UART/ADC/定时器）；
- 提供统一调度入口，便于逐步扩展业务逻辑；
- 作为“测试模板”，可用于逐项验证板级功能是否正常。

---

## 2. 代码框架说明（整体架构）

### 2.1 目录结构

```text
.
├── src/                # 用户应用代码（建议主要在这里开发）
├── ra_gen/             # FSP 自动生成代码（外设实例、初始化、向量等）
├── ra_cfg/             # FSP 配置头文件
├── ra/fsp/             # FSP 库源码
├── renesas_prj.uvprojx # Keil 工程
└── README.md
```

### 2.2 分层关系

- **BSP/FSP 层**：`ra/`、`ra_gen/`、`ra_cfg/`
  - 负责芯片底层启动、时钟、驱动实例与 HAL API。
- **应用层**：`src/`
  - 面向业务逻辑，封装按键、LED、串口、ADC、任务调度等。
- **主入口**：`src/hal_entry.c`
  - 系统初始化后进入主循环，并按周期调用应用任务。

### 2.3 执行流（简化）

1. 芯片启动与 FSP 初始化；
2. 进入 `hal_entry()`；
3. 周期调用调度器；
4. 调度器分发按键/LED/采样/通信等任务；
5. 根据按键和采样结果执行控制逻辑。

## 3. 测试模板已实现功能

当前模板主要覆盖以下“可直接验证”的功能模块：

1. **按键检测与事件边沿识别**
   - 低电平按下；
   - 提供按下边沿 `key_down` 与抬起边沿 `key_up`；
   - 支持 K2/K3/K4 三个按键状态位。

2. **LED 控制**
   - 提供 LED 点亮/熄灭或状态控制接口；
   - 可用于联动按键事件做可视化验证。

3. **ADC 采样**
   - 读取传感器/模拟量输入；
   - 可通过串口打印或逻辑判断进行结果验证。

4. **UART 通信**
   - 串口发送调试信息；
   - 用于输出系统状态、按键事件、采样值。

5. **定时器与任务调度**
   - 周期触发任务处理；
   - 保证按键扫描、采样、通信有固定节拍。

6. **模式控制示例**
   - 已内置 K2 切换 `system_mode` 的示例逻辑，演示输入事件如何驱动系统状态机。

## 5. 按键逻辑说明（本次修复）

按键为**低电平按下**，使用状态位图进行检测：

- `KEY2_MASK = 1 << 0`
- `KEY3_MASK = 1 << 1`
- `KEY4_MASK = 1 << 2`

事件定义：

- `key_down`：按下边沿触发（0→1）
- `key_up`：抬起边沿触发（1→0）

边沿计算：

- `key_down = key_val & ~key_old`
- `key_up   = key_old & ~key_val`

> 这样可以确保“按下”和“抬起”事件语义不同，避免同样触发的问题。

## 7. 开发建议

- `ra_gen/` 下代码尽量通过 FSP 配置工具维护，避免手改被覆盖；
- 若按键存在抖动，建议在 `key_proc()` 外增加 10~20ms 周期采样或软件去抖；
- 中断与主循环共享变量时，按需增加 `volatile` 与临界区保护；
- 新增业务建议先放在 `src/`，并由调度器统一管理调用时机。

## 按键事件说明（已修复）

按键模块使用**状态位图 + 边沿检测**：

- `key_down`：仅在按下瞬间置位
- `key_up`：仅在抬起瞬间置位

按键与位定义：

- K2 → `KEY2_MASK` (`1 << 0`)
- K3 → `KEY3_MASK` (`1 << 1`)
- K4 → `KEY4_MASK` (`1 << 2`)

这样可以避免“按下与抬起触发标志一致”的问题，也支持多个按键同时检测。
